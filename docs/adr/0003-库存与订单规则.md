# ADR-0003 库存与订单规则

- 状态：已接受（2026-08-22；M3 实现）
- 来源：`IMPLEMENTATION_BRIEF.md` §5–§6、`docs/plan/03` P0-4～P0-7

## 决策

1. **库存分离**：`skus.stock`（实物）与 `skus.locked_stock`（已锁）；可售 = `stock - locked_stock`；DB 约束 `check(stock >= locked_stock >= 0)`。
2. **下单锁定（事务）**：逐 SKU `UPDATE skus SET locked_stock = locked_stock + :q WHERE id = :id AND stock - locked_stock >= :q`；影响 0 行 → 抛「库存不足: <sku>」整单回滚；随后写 `orders(PENDING_PAYMENT, expire_at = now + ORDER_EXPIRE_MINUTES)`、`order_items` 快照、`payments(INIT)`、`inventory_logs(lock)`，并移除购物车中对应已勾选项（立即购买不动购物车）。
3. **支付成功**：`stock -= q, locked_stock -= q` + `inventory_logs(deduct)`；`payments=SUCCESS`、`orders=PAID`、写 `paid_at`。
4. **取消 / 超时**：`locked_stock -= q` + `inventory_logs(unlock)`；`orders=CANCELLED`、写 `cancelled_at`。
5. **运费**：合计 ≥ 9900 分免运费，否则 1000 分；`pay_amount = total_amount + freight`。
6. **状态机**：`PENDING_PAYMENT → PAID → SHIPPED → COMPLETED`；`PENDING_PAYMENT → CANCELLED`；其余迁移抛错；每次迁移写对应时间戳。
7. **Mock 支付幂等**：同 `transaction_no` 重复 / 订单已 PAID → 返回成功且不重复扣减；订单 CANCELLED → 400。
8. **超时处理**：读取订单（详情/列表/支付页）时惰性取消；`POST /api/cron/expire-orders`（`x-cron-secret`）与后台按钮批量处理。
9. **购物车**：同 SKU 合并；`1 ≤ qty ≤ min(可售, 99)`；条目 ≤ 50；SKU 下架或可售 0 → 失效、不可勾选、不计合计；结算预览与提交都重新校验。
10. **并发验证**：库存 10 的 SKU 并发 50 次各买 1 件 → 恰好 10 单成功、`stock=10, locked=10`，支付后 `stock=0, locked=0`，无负数（`tests/unit/inventory.concurrency.test.ts`）。

## 后果

- 不做多仓、预警、退款；历史订单展示快照，不受改价/下架影响。
- 并发正确性依赖 Postgres 行级锁 + 条件更新，不依赖应用层锁。
